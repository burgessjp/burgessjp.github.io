## 1. 背景与目标

做一个朋友间分享娱乐用的 MBTI 性格测试。核心诉求：**体验流畅、结果页有分享欲、一个文件就是全部**。

成功标准：

- 60 题流程一口气做完成功率高（一次一题、自动前进、防误刷新）
- 结果页信息完整：类型 + 四维度倾向条 + 详细解读 + 扩展分析
- 一键生成可保存/转发的分享卡片
- 断网状态下双击 `index.html` 完全可用（零外部资源）
- 手机（375px / 320px 宽）布局正常

非目标（明确不做）：

- 后端、数据收集、访问统计
- 16personalities 的第五维度（A/T 身份轴），只做经典 4 维度
- 多语言、题库后台、账号体系
- 二维码（需要引库，YAGNI；将来要再加）

## 2. 技术架构

单 HTML 文件，vanilla JS + 内联 CSS，零依赖零构建。三个屏幕按 `phase` 状态切换（同一个 DOM 容器内渲染，非多页面）：

```
欢迎页 (welcome) → 答题页 (quiz) → 结果页 (result)
```

- **欢迎页**：标题、一句话介绍、「60 题 · 约 8 分钟」、开始按钮
- **答题页**：一次只显示一题，顶部进度条（`n / 60` + 进度条），底部「上一题」按钮
- **结果页**：类型代码 + 称号 → 四维度倾向条 → 核心描述 → 优势/短板 → 职业/名人/关系建议 → 分享卡片按钮 + 重新测试

计分逻辑为纯函数，与 DOM 解耦，集中放在 `<!-- SCORING-CORE-START/END -->` 标记的 script 块内，供 Node 断言脚本提取执行（见 CLAUDE.md 代码约定）。

## 3. 题库设计

### 3.1 结构

- 经典 4 维度：`EI`（外向/内向）、`SN`（实感/直觉）、`TF`（思考/情感）、`JP`（判断/知觉）
- **60 题，每维度 15 题**，固定题库（非随机生成）
- 每维度 `dir: +1` 恰好 8 题、`dir: -1` 恰好 7 题（15 为奇数无法绝对均衡；8/7 的轻微差在「全选同意」下只造成 53% 倾向，可忽略，且让断言的期望类型可硬编码）
- 每次测试开始时用 Fisher–Yates 打乱题目顺序（仅影响展示顺序，不影响计分，计分按题目 id 索引答案）

### 3.2 题目 schema

```json
{ "id": "q17", "dim": "SN", "dir": -1, "text": "我常在聊天中突然联想到毫不相关的新点子。" }
```

- `dir: +1` 表示「同意」指向该维度第一极（E / S / T / J）；`dir: -1` 指向第二极（I / N / F / P）
- 陈述句第一人称、口语化、覆盖社交 / 决策 / 工作方式 / 生活习惯四类场景，不学术腔
- 正反方向混排：同意「我就是派对核心」与同意「聚会后我需要独处回血」分别指向不同极

### 3.3 作答量表

5 点 Likert，固定标签与分值：

| 非常不同意 | 不同意 | 中立 | 同意 | 非常同意 |
|---|---|---|---|---|
| -2 | -1 | 0 | +1 | +2 |

## 4. 计分算法

```
raw(dim)  = Σ (answer[q] × q.dir)   对该维度 15 题
pct       = 50 + |raw| / 30 × 50    // 映射到 50–100，四舍五入取整
pole      = raw > 0 ? 第一极(E/S/T/J)
          : raw < 0 ? 第二极(I/N/F/P)
          : 第二极(I/N/F/P)          // tie-break：0 分归第二极，展示 50%
type      = 四个维度的 pole 拼成四字母，如 "INFP"
```

- 维度倾向条双向展示：中点 50%，向获胜一极延伸 pct%，两侧标注字母与百分比
- 计分函数签名：`computeResult(questions, answers) → { type, dims: { EI: {pole, pct, raw}, SN: …, TF: …, JP: … } }`，纯函数、确定性（同输入同输出，不受题目展示顺序影响）

## 5. 16 类型内容

每个类型一个对象，schema：

```json
{
  "code": "INTP",
  "name": "逻辑学家",
  "tagline": "一句 15 字内的 slogan，用于分享卡片",
  "desc": "150–250 字核心描述，讲透这个类型怎么看世界、怎么行事",
  "strengths": ["3–4 条，每条一句话"],
  "weaknesses": ["3 条，每条一句话，坦诚但不贬损"],
  "careers": ["4–6 个适配职业方向"],
  "famous": ["3–4 位代表人物，公开流传的常见归类，娱乐性质"],
  "relationship": "80–150 字，和这个类型做朋友/恋爱怎么相处"
}
```

- 全部原创中文文案，基于类型学公开共识撰写
- 名人代表使用流传最广的归类（如爱因斯坦＝INTP），虚构角色可作补充；文案避免对真实人物的主观断言

## 6. 分享卡片

- **Canvas 自绘 PNG**：不 drawImage 任何外部图片、不引外部字体，直接 `toDataURL('image/png')`
- 竖版卡片（3:4），内容：类型代码（大字）+ 称号 + tagline + 四维度条 + 底部小字「MBTI 性格测试」
- 获取与转发：
  - 支持 Web Share API 且可分享文件时（`navigator.canShare({ files })`）：一键系统分享 PNG
  - 否则展示生成的图片：移动端长按保存，桌面端提供下载按钮（`<a download>`）

## 7. 状态管理与进度恢复

localStorage，key `mbti-test-state`，结构：

```json
{
  "v": 1,
  "phase": "quiz",
  "order": ["q3", "q41"],
  "answers": { "q3": 2 },
  "index": 11,
  "result": null
}
```

- 答题页每次作答/翻页后写入；刷新后读取恢复到原位置
- 完成后 `phase: "result"` 并写入 `result`；再次打开直接展示上次结果
- 「重新测试」清空存储回到欢迎页
- 版本号 `v` 不匹配（将来格式变更）→ 丢弃旧存储
- 所有 localStorage 访问包 try/catch（隐私模式等不可用场景降级为不持久化，当前会话内流程不受影响）

## 8. 视觉与交互

- **移动端优先**：单栏布局，兼容到 320px 宽；桌面端居中限宽（~480px）
- 系统字体栈，无外链字体
- 答题交互：点选后高亮反馈约 200ms 再自动进下一题；「上一题」可回退，回退后展示已选值，可改
- 动效克制：题目切换、进度条、结果条生长用轻量 CSS transition；尊重 `prefers-reduced-motion`
- 量表按钮为真实 `<button>`，可键盘操作
- 具体视觉风格（配色、气质）在实现阶段用 frontend-design 打磨，目标是「有记忆点、不像通用 AI 模板」，硬约束是不引外部资源

## 9. 边界与降级

| 场景 | 行为 |
|---|---|
| 刷新/误关后重开 | 恢复到答题位置或上次结果 |
| localStorage 不可用 | 降级为不持久化，当次会话正常完成 |
| 维度得分为 0 | tie-break 归第二极（I/N/F/P），展示 50% |
| 连点/重复作答 | 同题重选覆盖旧值；自动前进有 200ms 间隔不会连跳 |
| 微信内浏览器 | 无外部资源 → 完整可用；分享卡片走长按保存（微信不支持 Web Share files） |
